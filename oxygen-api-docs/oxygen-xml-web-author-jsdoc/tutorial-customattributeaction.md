## Implementing a Custom Action for Editing an Attribute Value

To provide custom functionality for editing attributes values in the Attributes View, you can implement a custom attribute action provider. This allows you to define how specific attributes should be edited when users interact with them.

## Implementing the Attribute Action Provider

Suppose you want to provide a custom URL chooser when editing `href` attributes. Here's how you can implement this:

```
workspace.listen(sync.api.Workspace.EventType.EDITOR_LOADED, function(e) {
  e.editor.registerAttributeActionsProvider({
    getAction: function(elem, attr) {
      var action = null;
      if (attr === 'href') {
        action = new sync.actions.AttributeEditingAction(function(currentValue, done) {
          // Show the url chooser.
          var context = new sync.api.UrlChooser.Context(sync.api.UrlChooser.Type.GENERIC);
          var urlChooser = workspace.getUrlChooser();

          var urlChoosen = function(url) {
            if (url === null) {
              // Do not change anything.
              done(currentValue);
            } else {
              done(url, true);
            }
          };
          urlChooser.chooseUrl(context, urlChoosen, sync.api.UrlChooser.Purpose.CHOOSE);
        }, 'Open24');
      }
      return action;
    }
  });
});

```

This code does the following:

1. Listens for the `EDITOR_LOADED` event to ensure the editor is ready
2. Registers an attribute actions provider using `registerAttributeActionsProvider`
3. Implements the `getAction` method that returns a custom action for specific attributes
4. For `href` attributes, creates an `AttributeEditingAction` that:

    * Shows a URL chooser dialog
    * Handles the URL selection result
    * Updates the attribute value with the chosen URL

## How It Works

When a user interacts with an attribute in the Attributes View:

1. The editor checks if there's a custom action provider registered for that attribute
2. If found, a special edit button appears next to the attribute's value field
3. When the user clicks this button, the editor calls the `getAction` method with the current element and attribute name
4. If the provider returns an action for that attribute, it's used instead of the default attribute editor
5. The action's callback is executed, which can show custom UI (like a URL chooser) for editing the attribute
6. Once the user completes the action (e.g., selects a URL), the attribute value is updated with the new value

This provides a more intuitive way to edit complex attributes, as users can easily identify which attributes have special editing capabilities through the presence of the edit button.
